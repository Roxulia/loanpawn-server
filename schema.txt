LonePawn Server Schema Snapshot
Source: current files under database/migrations

Conventions
- Primary tenant table: client_tenants
- Tenant foreign key rule: every table with a tenant_ or pawn_ prefix uses tenant_id as a foreign key to client_tenants.id
- In the current migrations, some tenant-prefixed tables already declare tenant_id explicitly
- Several pawn_/tenant_ tables are still skeletal and do not yet declare tenant_id in code; this file documents the intended tenancy rule for them

Reference
- PK = primary key
- FK = foreign key
- nullable = column allows null
- default(x) = column default value

Relationship Summary
- master_client_sessions.client_id -> master_clients.id
- master_admin_sessions.admin_id -> master_admins.id
- client_tenants.client_id -> master_clients.id
- tenant_expense_types.tenant_id -> client_tenants.id
- tenant_material_types.tenant_id -> client_tenants.id
- tenant_interest_types.tenant_id -> client_tenants.id
- By tenancy convention, all remaining tenant_* and pawn_* tables should also use tenant_id -> client_tenants.id
